# Contribution policy

**Owner:** Maintainers · **Review:** every 6 months · **Questions:** GitHub Discussions · **Enforcement:** non-conforming PRs are asked to change or are closed with a reason.

## Eligibility

Anyone may contribute, subject to the [Code of Conduct](../CODE_OF_CONDUCT.md).

## Workflow

Issue → branch → focused PR → CI green → maintainer review → merge. See [CONTRIBUTING.md](../CONTRIBUTING.md).

## Tests

User-visible behavior changes need tests and documentation. Bug fixes need a regression test.

## Review

- At least one maintainer review for normal PRs.
- Two reviews for security-sensitive changes (run-record redaction, config loading, CI action) when feasible.
- Nobody approves their own PR.
- Exceptions are documented in the PR, never quietly bypassed.

## Authorship and sign-off

Contributors keep authorship in Git history. No CLA. The PR template's checkbox confirms the contributor has the right to submit the work under the project license. DCO sign-off is not required at this stage.

## Conflicts

Reviewers with a conflict of interest (e.g. a competing product or a paid engagement) disclose it and step back.

## AI-assisted code

Follow the [AI-assisted contribution policy](ai-assisted-contribution.md).

## What we don't promise

Contributing does not create employment, a credential, scholarships or admissions benefits.
