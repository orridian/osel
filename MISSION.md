# Mission

**Build software that other people genuinely depend on.**

## Beneficiaries

- Developers who need to know whether a change made their system better or worse.
- Researchers who need evaluations that someone else can rerun and inspect.
- Contributors who want to learn real engineering practice on a project with clear standards.

## Intended impact

- Evaluation results that carry their own evidence: dataset identity, configuration, code version and environment.
- Fewer silent regressions, because CI compares runs against a baseline with explicit thresholds.
- Honest reporting, including uncertainty and limitations.

## Boundaries

OSEL does **not**:

- claim to "revolutionize" anything; claims are limited to what evidence supports;
- collect user data by default (telemetry is off and does not exist);
- run hosted services, accounts or a SaaS platform before real demand is demonstrated;
- claim partnerships, endorsements or users that cannot be verified.
